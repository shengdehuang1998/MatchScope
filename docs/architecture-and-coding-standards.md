# 技术架构与编码规范

## 当前实现与待实现目标

本文件补齐仓库原有文档链接指向的规范文件。阶段范围见[第一阶段开发清单](phase-1-development-checklist.md)，业务角色约定更新于 2026-09-30。

当前实现采用 npm workspaces、TypeScript、Fastify API、Expo React Native 手机端、React 管理后台及 Drizzle/PostgreSQL。已有认证、注册、按用户归属的比赛及分析模板接口、模板内容版本记录；尚未实现 admin/user 角色隔离、共享业务数据访问及完整比分、盘口和预测方向展示。新业务要求不得标注为已完成，检查项以实际验证和验收为准。

## UI 组件规范

### UI 组件库选型（已基础接入，真机待验收）

| 端           | 组件库                                   | 用途                                                           |
| ------------ | ---------------------------------------- | -------------------------------------------------------------- |
| Web 管理后台 | Ant Design（antd）                       | 管理表格、表单、筛选、弹窗、导航及状态反馈                     |
| 手机端       | React Native Paper（react-native-paper） | 按钮、输入框、卡片、对话框及状态反馈，覆盖管理员与普通用户页面 |

已完成基础接入：后台使用 Ant Design ConfigProvider、简体中文语言包、主题和 Layout/Menu/Card/Result 等组件；手机端使用 PaperProvider、统一主题和 Expo 图标，现有 ui.tsx 的输入框、按钮、校验提示及加载状态已迁移至 Paper，设置开关及底部导航图标同步接入。现有业务卡片与布局继续保留，完整业务页面定制及双角色权限仍待实现；iPhone 真机交互待验收。

基础接入验证：手机端 TypeScript 检查、受影响代码 ESLint、后台生产构建及 Expo iOS/Web 导出已通过。打包验证不等于真机交互验收，iPhone 键盘、触摸、长文本与界面显示仍待手工验收。

手机端统一配置 PaperProvider 和主题，后台统一配置 Ant Design ConfigProvider、主题及简体中文语言包。两端共享产品颜色、字体层级、间距和状态语义，各自使用对应组件库；业务组件仍按比赛、比分、盘口及预测方向封装。默认英文、日期与校验提示均需检查并转换为简体中文。

接入前验证组件库与仓库 React、Expo、React Native 版本及依赖的兼容性。保留现有 API、表单和权限边界，将通用 UI 封装逐步迁移到选定组件库，不并行维护重复的基础样式体系。

## 业务职责与权限目标

- 普通用户查看可展示的比赛、比分、盘口、预测方向及历史结果，仅修改本人偏好。
- 管理员拥有查看功能，并负责比赛维护、比分与盘口录入、分析模板名称与内容编辑、启停和默认配置。手机端应支持管理员业务处理。
- 分析模板内容及版本仅供管理员管理与内部追溯；系统自动绑定启用版本，普通用户不选择模板，也不读取模板内容。
- 内容版本不可变，修改不能覆盖历史引用。名称修改不生成新的内容版本。
- 后端逐接口检查服务端角色及数据范围，客户端隐藏入口不能代替授权。注册不能指定管理员角色，身份分配使用受控服务端流程。
- 管理员权限撤销后不得因旧令牌继续保留权限。个人设置及会话保持用户隔离，管理员业务操作记录审计信息。
- 现有用户归属模型向管理员维护、用户查看模式迁移时，明确业务可见范围，保留已有数据和版本引用，不将所有旧账户自动提升为管理员。
- 第一阶段人工维护真实比分与盘口，缺失数据和未生成预测显示中文空状态。AI 预测、定时任务、第三方数据及正式邮件为第二阶段规划。

## 分层与依赖

- apps/mobile 和 apps/admin 通过 API 访问数据，不连接数据库。
- apps/api 负责协议、认证和用例编排；业务规则放在 packages/domain，不能写入 React 页面。
- packages/contracts 是共享 Schema、DTO、协议、错误码与枚举的来源。
- packages/domain 保存框架无关的模型、权限规则与 Repository 接口，不依赖 Fastify、React 或 Drizzle。
- packages/database 保存数据库模型、查询、事务、迁移和种子实现；路由不得直接执行数据库查询。
- 下层不反向依赖应用。第一阶段保留模块化单体，未来 Worker 复用共享包，不提前拆微服务。

## 数据与接口

- PostgreSQL 是业务状态的唯一事实来源，所有写入通过后端权限与输入校验。
- API 前缀为 /api/v1，使用共享 Schema；列表设置分页上限。
- 数据库迁移显式执行，多表写入使用事务，保留外键、唯一约束与必要索引。
- 时间按 UTC 保存并传输带时区的 ISO 8601 字符串，页面按用户时区显示。
- 业务数据删除优先采用状态处理，仅无引用草稿允许物理删除。
- 比赛、分析和通知分别建模，不混合状态；比分维护不能因比赛已开赛而被排期编辑规则阻止。

## 文案、配置与质量

- 手机端和管理后台所有用户可见文案使用简体中文，包括校验、弹窗、加载、空状态、权限提示及成功与失败反馈。
- 后端供前端展示的错误信息使用简体中文；外部英文异常转换为中文提示并提供中文兜底，不直接展示技术异常。
- 字段、协议、错误码和枚举保留英文命名，界面映射为简体中文，统一产品术语“分析模板”。
- 环境变量集中校验，密钥仅在后端保存；EXPO_PUBLIC_ 配置均视为公开信息。日志不输出密码、令牌或密钥。
- 遵循仓库 TypeScript、ESLint、Prettier 配置。按变更范围检查，权限变更验证直接调用接口、深链、角色撤销及个人数据隔离。
- 纯文档变更检查内容、链接及当前实现与规划的区分。保留既有未提交改动，架构或业务约定变化同步更新文档。
